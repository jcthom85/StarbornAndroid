# World 2 Part 1 — approved critical fixes

October 30, 2026. Implemented locally, with Android debug APK built. Resident characterization/placement (#7) is deliberately untouched. The later attachment is [categorized separately](../playtest/reports/starborn_world2_part1_second_half_notes.md); new issues in it are not automatically included in this repair authorization.

## Changes

1. **Fishing result crash:** `FishingResultPayload` now implements Serializable so Android's SavedStateHandle accepts the result delivered as soon as a catch reaches RESULT. Previously it was an unsupported plain object. A regression exercises the actual SavedStateHandle assignment and serialization round trip, including quantity and the `secured` flag. Existing real-cast tests verify catch inventory and journal delivery without repeat awards. This is a source-confirmed crash cause; fresh phone catch/return acceptance remains required.
2. **David/Megan dialogue exit accessibility:** both authored roots already contain unconditional terminal leave options. The response list is now bounded and scrollable, with leave options shown first, so lengthy topic menus cannot push the exit out of the available phone area. Existing terminal-choice and reward tests pass; physical phone layout remains to be checked.
3. **Toggle exit correctness:** the controller identifies gates driven by authored toggle states, re-evaluates their requirements, and avoids turning them into permanent unlocks. It also ignores legacy permanent-unlock receipts for those gates. Waterlogged Tunnel south is initially blocked, opens on drainage, closes on flooding and survives save/reload correctly. This same rule protects the analogous optional toggle gates without changing permanent key/enemy unlocks.
4. **Minimap node exits:** compact directional markers are now drawn for node exits on the minimap, using its existing exit data and blocked-state colors. Labels/service icons remain outside this small marker treatment. Existing map-state tests verify exits without remote-room clutter and preserve darkness/preview restrictions. Long in-node connections whose other endpoint is outside the viewport are a separate new report from the attachment, still pending.
5. **Completed journal groups:** actual campaign titles replace World 1/World 2 labels on Android and desktop, with campaign order preserved and Other quests last. Active-quest organization is unchanged.
6. **Crash narrative/HP consistency:** Zeke has a torn suit seal rather than a forced injury. Dialogue, quest summary/objective, treatment event, completion message and crash-site prose agree that the medkit's pressure tape/bio-sealant repairs his suit. HP and party membership are unchanged. Existing task/event/milestone IDs remain compatible with saves.
7. **Unlimited REST:** when a one-time camp event has already run, its REST option performs ordinary party rest instead of silently dispatching an exhausted event. Full-health parties still receive normal rest feedback. First-visit supply grants remain one-time; unlimited rest is not unlimited Neural Stabilizers. Repeatable story/rest events still use their existing paths.
8. **Exploration action state:** Botanist scans, Tideglass gathering and conduit salvage use active-quest visibility, with salvage additionally waiting for Astra inspection. Their completed events retire the action. Passive generic/inspect interactions persist a per-room read receipt keyed to their current message and room description; read text uses a subdued, normal-weight treatment while staying usable. Different information produces a fresh receipt key and the unread appearance. Event actions, puzzles, toggles and services are excluded from passive read treatment. Existing collected-container disappearance remains intact.
